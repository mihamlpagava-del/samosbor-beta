# САМОСБОР — G MODE (FPS SHOOTER OVERHAUL + ONLINE)
## АУДИТ ТЕКУЩЕЙ АРХИТЕКТУРЫ И ПЛАН РАЗВИТИЯ (PHASE 00)

**Дата составления:** Ноябрь 2026 г.  
**Целевая платформа:** Web / Desktop / VK Games (HTML5 Canvas + Node.js Socket.IO)

---

### 1. ТЕКУЩАЯ АРХИТЕКТУРА И СТЕК ТЕХНОЛОГИЙ

1. **Сервер:** Node.js + Express + Socket.IO v4.
   - Персистентность: локальное хранилище состояний в `database.json` с ротацией бэкапов.
   - Сеть: событийная модель Socket.IO. В игре уже есть 4-player PvE raid squad система для текстово-кликерного режима (`coopSquads`, `broadcastToSquad`, `raidCombatTick`, волны 1–11, голосования, распределение лута), а также пошаговый PvP-колизей.
   - Рейд в реальном времени (`radarRoguelike.js`) в текущей версии запускается **на стороне клиента**, а серверу отправляется только финальный отчёт `socket.emit('radarRaidComplete', ...)`.

2. **Клиентский стек:** Чистый Vanilla JavaScript (ES6+), HTML5 Canvas 2D API, Web Audio API.
   - **Движок 3D:** Отсутствуют сторонние тяжелые библиотеки вроде Three.js или Babylon.js. Режим от первого лица (G-Mode) реализован на базе **кастомного 2.5D DDA Raycaster (Wolfenstein 3D / Build Engine стиль)**, отрисовываемого через 2D контекст Canvas (`ctx.fillRect`, `createLinearGradient`, `drawImage`).
   - **Двойной режим камеры (Dual-Mode):** Мгновенное переключение клавишей `G` между:
     - `TDS` (Top-Down Shooter) — изометрический/ортогональный тактический вид сверху с радаром.
     - `FPS` — режим от первого лица с псевдо-3D коридорами, полом, потолком, биллбордами монстров и процедурным оружием.

### 3. СЕТЕВАЯ АРХИТЕКТУРА (PVE 2-4 ИГРОКА И PVP ARENA)

Для масштабирования G-Mode в мультиплеер не требуется переписывать сетевой стек с нуля. Используется архитектура **Server-Authoritative Room State** на базе существующего Socket.IO:

```
[Client 1 (G-Mode)]   \                          /--> [Node.js Server (server.js)]
[Client 2 (G-Mode)]    ===> (Socket.IO Events) ===>   Room State Tick (25-30 Hz):
[Client 3 (G-Mode)]   /                          |    - Monster A* & Positions
[Client 4 (G-Mode)]  /                           |    - Bullet Traces & Hitreg
                                                 |    - Door States & Loot Sync
                                                 \==> Client Interpolation & Prediction
```

1. **Комнаты рейдов (`samosborRooms`):**
   - Сервер хранит сид уровня, чтобы BSP-генерация на всех клиентах создавала идентичную геометрию.
   - Клиенты передают свой вектор ввода и угол взгляда: `socket.emit('playerMove', { x, y, angle, shooting })`.
   - Сервер синхронизирует монстров, двери и здоровье игроков с частотой 25 Hz (`socket.emit('roomTick', snapshot)`).
2. **PvP-мод / PvPvE:**
   - Модель повреждений с проверкой попаданий на сервере по лучам от позиции стрелка.
   - Дружественный огонь (Friendly Fire) и режим ликвидатора-предателя.

### 4. ПОШАГОВЫЙ ПЛАН ВНЕДРЕНИЯ (PHASES 01–10)

- **PHASE 01 — Окружение и текстурирование:** Наложение текстур стен из `public/assets/radar/tiles/` в рейкастер, прорисовка кирпичной кладки, бетона, кабелей и настенных гермодверей.
- **PHASE 02 — Оружие и VFX:** Спрайтовые текстуры для 10 типов оружия от 1-го лица, дульные вспышки, брызги слизи/крови на стенах, отдача.
- **PHASE 03 — Расширенный бестиарий:** Внедрение 33 типов врагов с уникальными биллбордами, поведением и звуками агрессии.
- **PHASE 04 — Поиск пути (A* Pathfinding):** Навигационная сетка по комнатам и коридорам, обход углов и дверей монстрами.
- **PHASE 05 — Интерактивные объекты:** Взлом терминалов, вентили сброса пара, запертые ящики, ловушки.
- **PHASE 06 — Сетевой PvE Кооп (2–4 игрока):** Синхронизация аватаров напарников, подсветка маркеров, совместное открытие шлюзов.
- **PHASE 07 — Сетевой PvP / PvPvE:** Арена выживания, дуэли ликвидаторов, эвакуация только для выживших.
- **PHASE 08 — Оптимизация и мобильная адаптация:** Стабильные 60 FPS на Canvas 2D / WebGL fallback, оптимизация лучей (DDA).
- **PHASE 09 — Полировка звука и атмосферы:** Пространственный 3D-звук (Web Audio PannerNode) для шагов и рыков монстров.
- **PHASE 10 — Финальное тестирование и релиз в продакшен.**
